# Data model

If you change any of these shapes, update this file in the same PR.

## `taxonomy.json` (bundled resource)

Generated by `tools/gen_taxonomy.py` from Wikidata and English Wikipedia; the species are
listed in `tools/species.txt`. Never edit by hand (`--check` catches it). Where each value comes
from is recorded in `tools/taxonomy-sources.json`. A single root `Taxon` (the kingdom) decoded
with `JSONDecoder` into `Taxon`.

```json
{
  "id": "animalia",              // stable, lowercase; used in saved preferences. Never rename casually.
  "name": "Animal",              // English Wikipedia title of the taxon, else its scientific name
  "scientificName": "Animalia",
  "rank": "kingdom",             // kingdom | phylum | class | order | family | genus
  "children": [ /* Taxon */ ],   // optional
  "species": [                   // optional; normally on family (or genus) nodes
    {
      "wikiTitle": "Snow leopard",      // English Wikipedia article title; also the species id
      "commonName": "Snow leopard",     // article title, or Wikidata P1843 if the title is scientific
      "scientificName": "Panthera uncia",
      "status": "VU"                    // Wikidata P141; EX for fossil taxa; else taxobox IUCN status; else NE
    }
  ]
}
```

Notes:

- Taxon `id`s are persisted in user preferences (`selectedTaxonIDs`). Renaming an id silently
  drops that selection for existing users.
- Species `id` is `wikiTitle`. Every entry is a species or subspecies on Wikidata (P105);
  `gen_taxonomy.py` refuses genus articles such as "Smilodon" (AGENTS.md rule 1, D-015).
- `EX` drives `Species.isExtinct`, which gates the extinct filters and artwork.

### ID changes in the W4 species expansion (2026-11-06, PR #12)

The list grew from 77 to 361 species. Genus-level entries were dropped because the generator
now refuses anything that isn't a species or subspecies on Wikidata. No migration: nothing has
shipped. Saved selections or Met entries with these ids simply stop matching.

- Species ids removed: `Smilodon`, `Tyrannosaurus`, `Triceratops`, `Stegosaurus`, `Tuatara`,
  `Dryococelus`, `Meganeuropsis`, `Jaekelopterus`, `Blanket octopus` (now the species
  `Common blanket octopus`). The onboarding fossils tile moves off `Smilodon` (W3).
- Taxon ids removed (no species left under them): `ceratopsidae`, `eurypterida`,
  `meganeuridae`, `meganisoptera`, `ornithischia`, `phasmatidae`, `phasmida`, `pterygotidae`,
  `rhynchocephalia`, `sphenodontidae`, `stegosauridae`, `tyrannosauridae`.
- No existing taxon id was renamed; all other changes are additions.

### ID changes in the Wikidata rebuild (2026-11-06, PR #9)

No migration is needed: nothing has shipped, so no saved preferences or species-met data use the
old ids.

- Taxon ids removed (Wikidata's tree differs): `actinopterygii`, `cetacea`, `dictynidae`,
  `dinosauria`, `eurypterida-2`, `neomphalina`, `pachydiscidae`, `phasmatodea`, `urodela`.
- Taxon ids added: `actinopteri`, `caudata`, `cybaeidae`, `desmoceratidae`, `myrmecobiidae`,
  `neomphalida`, `nestoridae`, `ornithischia`, `phasmida`, `raphidae`, `teleostei`.
- Species ids (`wikiTitle`) changed to the canonical article title: Hairy frogfish → Striated
  frogfish, Otodus megalodon → Megalodon, Atlas moth → Attacus atlas, Orchid mantis →
  Hymenopus coronatus, Dryococelus australis → Dryococelus, Chrysomallon squamiferum →
  Scaly-foot gastropod, Hypsibius exemplaris → Hypsibius dujardini.

| `MediaTag` | same | `historicalPhoto` / `realFossil` / `reconstruction`, derived (never stored) from the image and species: artwork → reconstruction; extinct + `isFossil` → real fossil; other extinct → historical photo; living → none. |

## Saved preferences (`UserDefaults`)

Key: `preferences.v1`. JSON-encoded `PreferencesStore.Stored`:

| Field | Type | Default |
| --- | --- | --- |
| `selectedTaxonIDs` | `Set<String>` | `[]` (whole kingdom) |
| `includeExtinct` | `Bool` | `true` |
| `extinctOnly` | `Bool` | `false` |
| `showArtwork` | `Bool` | `true` |
| `surpriseMe` | `Bool` | `true` |
| `hasOnboarded` | `Bool` | `false` (added with the concept screens) |
| `liveCatalog` | `Bool` | `true` ("Explore the full species catalogue", D-012) |

Every field is decoded with `decodeIfPresent`, so data saved before a field existed still loads.
`PreferencesStore.extinctMode` (Living only / Include extinct / Extinct only) is a computed view
over `includeExtinct` + `extinctOnly`; it is not stored separately.

## Likes (`UserDefaults`)

Key: `likes.v1`. JSON array of `LikesStore.Entry`, newest first:

| Field | Type | Notes |
| --- | --- | --- |
| `id` | `String` | `Species.wikiTitle` |
| `commonName`, `scientificName` | `String` | Copied at like time |
| `isExtinct` | `Bool` | |
| `lineage` | `[LikeAffinity.Step]` | `{id, rank}` for each ancestor, so live species (not in the bundled tree) still steer the feed after relaunch. Ids may be bundled ids (`felidae`) or GBIF-only ids (`gbif-genus-panthera`) |
| `likedAt` | `Date` | |

No image is stored (stores keep ids, not content); a screen that shows a liked species looks its
photo up through the injected `SpeciesContentProvider`. Entries saved earlier with an `imageURL`
field still decode (the decoder ignores unknown keys), so the key stays `likes.v1`.

Separate from saves (`met.v2`): a save is a bookmark, a like is a feed signal.

## Species met (`UserDefaults`)

Key: `met.v2`. JSON array of `MetStore.Entry`, newest first met first. Stores ids, dates and
flags only: names, statuses and lineage of bundled species are looked up in `taxonomy.json` when
shown, so regenerated data never leaves stale text on a device.

| Field | Type | Notes |
| --- | --- | --- |
| `id` | `String` | `Species.wikiTitle` |
| `firstMet` | `Date` | When the intro card was first shown |
| `lastMet` | `Date?` on decode | Last time the intro card was shown; defaults to `firstMet` |
| `saved` | `Bool?` on decode | Bookmark / long-press; defaults to false |
| `savedAt` | `Date?` | When it was saved |
| `live` | `{species: Species, lineageIDs: [String]}?` | Only for live-catalogue species not in `taxonomy.json`: the `Species` the catalogue built (GBIF name, Wikidata status) and the bundled branch ids above it. Ignored, then dropped at launch, if the bundled tree later gains the species |

Tile photos come from the content provider's disk cache, not the store. An `imageURL` key written by
the first `met.v2` build is ignored on decode. Every field except `id` and `firstMet` is optional on decode, and entries decode one by one, so a
bad entry or a new field never wipes the collection.

**Migration from `met.v1`** (runs once when `met.v2` is missing): keeps `id`, `firstMet` and
`saved`; sets `lastMet = firstMet`. v1 can't tell bundled from live species, so
each entry gets a `live` record built only from its own v1 fields, with status Extinct if v1 said
so and Not Evaluated otherwise (never inferred, D-012). `RootView` then calls
`forgetCopies(of:)` to drop the records the bundled tree covers. `met.v1` is removed after the
migration.

If you add a field, give it a default so old data still decodes. If you make a breaking change,
bump the key (`preferences.v2`) and note the migration here.

## Species content cache (Caches directory)

Folder: `Library/Caches/species-content.v1/`, one file per species named
`ContentCachePolicy.fileName(forWikiTitle:)` (16 hex digits of a 64-bit FNV-1a hash + `.json`).
Each file is a JSON `ContentCachePolicy.Entry`:

| Field | Type | Notes |
| --- | --- | --- |
| `schema` | `Int` | `ContentCachePolicy.schema` (1). A mismatch is a cache miss |
| `wikiTitle` | `String` | Checked on read, so a hash collision is a miss |
| `fetchedAt` | `Date` | Fresh for 7 days; older copies are refetched, and used only if the network fails |
| `content` | `SpeciesContent` | Exactly what `WikipediaContentProvider` returned (after `ContentPolicy`) |

iOS may purge Caches at any time; the app just refetches. Writes are atomic. If `SpeciesContent`
changes shape, bump both `schema` and the folder name (`species-content.v2`); folders from older
versions are deleted on launch. Raw HTTP responses (JSON and image bytes) are also kept by the
512 MB `URLCache` created in `App/`. Decoded images are memory-only.

## Not persisted

Seen counts, dwell affinity, live-branch misses and the recent-species window in `SpeciesPicker`
live in memory and reset on launch. Like affinity is rebuilt from `likes.v1` at launch. The live
catalogue caches GBIF keys and counts per branch in memory only. (The species-met collection above is persisted; picker weighting is not yet.)
