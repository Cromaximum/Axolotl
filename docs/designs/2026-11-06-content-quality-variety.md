# Design: Content quality and variety (Phase 1.5, W4)

- Author: Claude (thread "Expand species variety and fact quality"), asked for by Maxwell Rhinelander
- Date: 2026-11-06
- Status: Design approved (architect thread, 2026-11-06): replace or drop genus entries in this PR; W4 owns the `--lint` step in `ios.yml`; discovery share stays exactly 30%

## Problem

Maxwell got the app running and asked for a round of UX polish (roadmap Phase 1.5). W4 makes the
feed feel richer and less repetitive without adding any new content source:

1. Facts that need context ("It was later...", "As a result...", citation residue, lists) still
   reach cards. Number-rich, self-contained sentences should win.
2. Photo sets can show near-duplicate files, small images and runs of three or more photos.
3. Only 77 bundled species; the launch target is a few hundred (Nov 6 decision), and the live
   catalogue can only search branches that exist in the bundled tree.
4. The picker can show two species from the same family back to back, and discovery picks follow
   the bundled list's skew (mostly mammals) instead of spreading across the tree.

## Where it goes

Services (pure logic) and Data only, all in files W4 owns. No views, models, stores or adapters.

| File | Change |
| --- | --- |
| `Services/FactExtractor.swift` | Stricter `score`: more context-dependent openers, drop citation residue (`et al.`, `pp.`, `ISBN`, `doi`, "see below"), drop list-like sentences (a colon, or 4+ commas), drop sentences that restate the taxonomy ("is a species of"). Bigger bonus for numbers with units. New near-duplicate check so two facts (or a fact and the lead) never say the same thing. Text stays verbatim: we only *choose* sentences. |
| `Services/ContentPolicy.swift` | `licensedImages` also drops images narrower than 640 px, with a short side under 400 px, or with an aspect ratio beyond 2.6:1 (strips, panoramas). (Changed from "short side under 500 px" while coding: Commons thumbs are capped at 1080 px wide, so 500 would have dropped ordinary 2:1 landscapes.) New pure `distinctImages(_:preferring:)` that drops near-duplicate files (same name once extension, "crop", "edit", version numbers and "(1)" suffixes are removed), keeping the lead image when it is one of the pair. |
| `Services/FeedComposer.swift` | Calls `distinctImages` with the lead file. Pacing: never more than two photo cards in a row; leftover photos are not run on at the end but reused as the backdrop of fact cards, and a fact card never repeats the photo of the card right before or after it. |
| `Services/SpeciesPicker.swift` | No same family back to back (falls back only when the pool has nothing else). Soft penalty (x0.5) for the same order as the last species. Discovery picks weight each species by 1/sqrt(species in its class within the pool), so a class with 3 species isn't drowned by one with 40. The 30% discovery share (D-001) is unchanged. Same rules in `choose` for live candidates. |
| `tools/species.txt` | Grow from 77 to about 300 species, spread across more classes, orders and families (fish, amphibians, invertebrates, more birds and reptiles), which also gives the live catalogue many more branches to search. The list only chooses *which* animals; every value still comes from Wikidata/Wikipedia (D-011). |
| `tools/gen_taxonomy.py` | Refuses entries whose Wikidata item is not rank species (P105 = Q7432) or subspecies (Q68947, proposed as D-015), refuses two lines that lead to one article, warns on articles with no free lead image or under 5,000 bytes, so rule 1 is enforced by the build, and reports them. New `--lint` mode that needs no network: checks `species.txt` for duplicates and that it matches `taxonomy.json` and `taxonomy-sources.json` one to one. |
| `Resources/taxonomy.json`, `tools/taxonomy-sources.json` | Regenerated by the script, never hand-edited. |
| `.github/workflows/ios.yml` | One extra step: `python3 tools/gen_taxonomy.py --lint`. Only file outside W4's list; asking the architect to allow it (roadmap W4 item 5). |

No new files besides this note. All of the files above stay under 300 lines.

## Data flow

Unchanged: `WikiClient` → `ContentPolicy.licensedImages` (now also size/aspect) →
`SpeciesContent` → `FeedComposer` (now dedupes and paces) → `FeedCard`. `FactExtractor` is still
called by `WikipediaContentProvider` with the same signature. `SpeciesPicker` keeps its public API;
it only remembers the last species' lineage inside `markShown`.

## New contracts

None. No model, `Codable` type, persisted key, protocol or JSON shape changes. `distinctImages` is a
new static function on `ContentPolicy`. `taxonomy.json` keeps its shape (more rows only).

## Content rules

No new source. Facts remain whole sentences copied verbatim from the species' own article; the
changes only reject more sentences. Images still come only from the species' Wikipedia article and
pass the same licence allowlist (no NC/ND). Extinct status still comes only from Wikidata P141 or
the fossil-taxon item (no keyword guessing). The species list picks which animals appear; no
names, statuses or groupings are typed in. No animal content is hard-coded in Swift.

## Tests

- `FactExtractorTests`: rejects context openers, citation residue, list sentences, taxonomy
  restatements; prefers numbers with units; drops near-duplicates of each other and of the lead;
  output sentences are exact substrings of the input (verbatim check).
- `ContentPolicyTests`: small and strip images dropped; `distinctImages` drops crops and format
  copies and keeps the lead.
- `FeedComposerTests`: never three photo cards in a row across many fact/photo mixes; fact
  backdrops differ from neighbouring photo cards; existing intro/no-two-facts tests still pass.
- `SpeciesPickerTests`: no same family back to back over 1,000 picks; the 70/30 split still holds;
  a small class gets a fair share of discovery picks against a large one.
- `--lint` runs in CI.
